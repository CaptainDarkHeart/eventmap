Pip-Boy Theme: Implementation and Porting Guide

Built 12 Oct 2026 in fundingmap/ (Tech Funding Map). Written so the same hidden theme can be ported to eventmap/ (techeventsmap.com) and astro-build/ (dantaylor.net). Palette and effect ideas credit: iosue-iulianus/homeassistant-pipboy-theme (MIT). All ASCII art and code here is original.

1. What it is

A secret, Fallout-style Pip-Boy terminal theme. Nothing in the UI advertises it. Visitors find it with the Konami code or by tapping the logo five times. On activation a ROBCO terminal boot sequence plays (with real, animated dataset stats on an ASCII device), then the whole site re-skins as a monochrome phosphor display with scanlines, vignette, glow and flicker. The Leaflet basemap is tinted to match.

4. How it works

4.1 Theme state

The site already toggled a dark class on <html>. Pip-Boy adds classes rather than replacing that system:

html.pipboy.pb-blue.dark     /* active: dark is kept so existing dark-only rules still apply */
html.pipboy.pb-amber.dark
html.pipboy.pb-green.dark

Turning it off removes pipboy and pb-*, deletes the storage key, and recomputes dark from the user's saved fm_theme or the OS preference (restoreBaseTheme()). The user's normal light/dark choice is never overwritten.

4.2 CSS strategy: variables, not rewrites

The existing site is styled entirely with CSS custom properties (--bg, --surface, --border, --text, --text-dim, --accent, --font, --mono). Pip-Boy simply redefines them from three per-variant inputs:

html.pipboy:root{
  --pb-fg:#4fd8ff; --pb-dim:#2a8aa8; --pb-bg:#00080d; --pb-hue:150deg; --pb-sat:3;
  --bg:var(--pb-bg);
  --surface:color-mix(in srgb,var(--pb-fg) 5%,var(--pb-bg));
  --surface-2:color-mix(in srgb,var(--pb-fg) 10%,var(--pb-bg));
  --border:color-mix(in srgb,var(--pb-dim) 55%,var(--pb-bg));
  --text:var(--pb-fg); --text-dim:var(--pb-dim); --accent:var(--pb-fg);
  --font:'Share Tech Mono','Courier New',monospace; --mono:var(--font);
}
html.pipboy.pb-amber{--pb-fg:#ffb642;--pb-dim:#b87a14;--pb-bg:#0d0800;--pb-hue:0deg}
html.pipboy.pb-green{--pb-fg:#1bff80;--pb-dim:#0fa855;--pb-bg:#0c0c0c;--pb-hue:100deg}

Adding a variant is one block of five values. Everything else follows.

4.3 CRT effects

  • Scanlines + tint: body::before, fixed, pointer-events:none, z-index:9000. A repeating-linear-gradient plus a 3% foreground tint. This pseudo-element is the only thing that animates (pb-flicker, opacity steps), so flicker is cheap and never touches the map.
  • Vignette: body::after, radial gradient to 55% black at the edges, z-index:9001.
  • Glow: text-shadow using the foreground colour at 55%, applied to headers, sidebar, cards, tables and popups only (not the whole body, to avoid blurring map labels).
  • Square corners: an :is(...) list of controls set to border-radius:0!important. Data dots (.dot, pulse rings) are deliberately excluded so pins stay round.
  • Readable fills: active tags, the assistant launcher and chat bubbles use color:var(--pb-bg) because the original #fff text is unreadable on a bright phosphor background.

4.4 Map tinting

html.pipboy .leaflet-tile-pane{
  filter:grayscale(1) sepia(1) hue-rotate(var(--pb-hue)) saturate(var(--pb-sat)) brightness(1.15) contrast(1.1);
}

sepia gives a base hue near 38°, then hue-rotate moves it to amber (0°), green (100°) or blue (150°). The basemap URL switches to dark_all because the dark class is on. The page registers PipBoy.onChange(...) to call tileLayer.setUrl(...) when the theme flips.

4.5 Triggers (pipboy.js)

  • Konami: a keydown listener on document walks a 10-key array. Letters are lower-cased. A wrong key resets progress (or sets it to 1 if the key is ArrowUp, so ↑↑↑↑↓↓… still works). Ignored when focus is in input, textarea, select or contenteditable, and during boot.
  • Logo taps: a click listener on .logo counts clicks within a 3s window. On the home page preventDefault() always runs (the link is a no-op there). Elsewhere the first click navigates home as normal, so the 5-tap trigger only completes on the map page. Known limitation.
  • Toggle: either trigger calls toggle(): off if active, otherwise set("blue").

4.6 Boot sequence

  1. set(variant) applies the classes first, then boot(variant) mounts #pb-boot, a fixed, opaque, z-index:10000 overlay. The page re-themes invisibly underneath.
  2. Stats load: Promise.race([warm(), 1200ms timeout]). warm() fetches /pb-stats.json once and caches the promise. It is called on the first Konami keystroke or the second logo tap, so the data is usually ready by the time the boot starts and ordinary visitors never request it. On failure the screen shows DATA LINK OFFLINE and the boot still plays.
  3. Art phase: the 12-line device frame reveals one row every 45ms with empty meters. Then requestAnimationFrame drives t from 0 to 1 over 1.6s. Each frame rebuilds the lines with value × smoothstep(t), so counters and bars animate together. All rows are padded to a fixed 30-column width so the frame never jitters.
  4. Text phase: starts 700ms after the art, so it overlaps the count-up. Characters type at 5ms each, lines pause 60ms, and the password line pauses 350ms for effect.
  5. Finish: 700ms after the last line, or immediately on click or any key, the overlay fades out over 350ms and is removed. All timers and the animation frame are cancelled.
  6. Reduced motion: static final frame, no typing, auto-dismiss after 1.2s.

Boot text (no em-dashes, per house style): ROBCO TERMLINK header, logon and password lines, LOADING FUNDING-MAP OS V7.1.0.8, MOUNTING VAULT-TEC FUNDING DATABASE ... OK, CALIBRATING EUROPEAN WASTELAND ... OK, PHOSPHOR: BLUE, WELCOME, OVERSEER.

4.7 Stats endpoint

// src/pages/pb-stats.json.ts
export function GET() {
  return new Response(JSON.stringify({
    rounds, totalEur, countries, sectors, disclosedPct, cityPct
  }), { headers: { "Content-Type": "application/json" } });
}

Built at astro build so it ships as a static dist/pb-stats.json and always matches the data in that deploy. At the time of writing: 7,248 rounds, EUR 180.9B, 35 countries, 31 sectors, 88% disclosed, 82% located.

5. Gotchas we hit

ProblemCause and fix
Active filters stayed mint green instead of the variant colourThe page's own html.dark{--accent:#2fd699} had equal specificity to html.pipboy{...} and won. Fixed by raising specificity to html.pipboy:root. Any port must check for a dark-mode rule that sets the same variables.
Theme script removed the dark class on loadThe page's init IIFE re-derived dark from saved light/dark, which broke the tile choice. Fixed by skipping it when PipBoy.active(), and by making applyTheme() a no-op while active.
Boot took over 8sPer-character delay was 14ms across about 30 lines. Cut to 5ms per character and 60ms per line.
Percent value touched the right borderRow content is exactly 24 columns, so a 6-cell bar plus label overflowed by one character. Bars are 5 cells.
Boot text clipped on short viewportsFont size is now clamp(12px, min(1.9vw, 2.2vh), 18px).
re.sub mangled backslashes when generating ASCII art into the JS fileOnly relevant if scripting edits: use a replacement function or slice the string, never pass art as a regex replacement template.

6. Accessibility and safety notes

  • Flicker and typing are off under prefers-reduced-motion.
  • The boot overlay has role="status" and an aria-label. It is skippable by click or any key.
  • Swatches have aria-label and title. Contrast for body text is high (bright phosphor on near-black). Dim text uses the darker phosphor tone, which is lower contrast by design and worth a check before porting to a content-heavy site.
  • All storage access is wrapped in try/catch, so private windows work (the theme simply does not persist).
  • Fonts load from Google Fonts (Share Tech Mono) via @import in pipboy.css. Self-host if the target project avoids third-party requests.

8. Port to astro-build/ (dantaylor.net portfolio)

More work. This project uses Tailwind with shadcn-style variables and a very different header, so treat it as an adaptation, not a copy.

9. Suggested refactor before the second port

Do this once, then every project becomes configuration:

  1. Replace the hard-coded selectors in pipboy.js with a config object read from window.PIPBOY_CONFIG or data-* attributes: logoSelector, hostSelector, baseThemeKey (fm_theme, em_theme, theme), statsUrl, bootLines, statRows.
  2. Split pipboy.css into a project-neutral effects file (scanlines, vignette, glow, boot, picker) and a small per-project variable map.
  3. Keep one copy in a shared folder (for example ~/Claude/shared/pipboy/) and copy at build time, so a fix lands everywhere.

10. Testing checklist

  • Konami code from a clean tab: boot plays in blue, theme applies, picker and exit appear.
  • Five logo taps (map page) does the same. Same triggers turn it off.
  • Reload while active: no boot, theme applied before first paint (no light flash), same variant.
  • Switch variants: colours, tile tint and active-filter colour all follow, no boot replay.
  • Exit: normal theme returns, matching the user's previous light or dark choice, tiles switch back, storage key cleared.
  • Typing "ba" or arrow keys in the search box does not trigger anything.
  • Reduced motion: static boot, no flicker.
  • Block /pb-stats.json in devtools: boot still plays, screen shows DATA LINK OFFLINE.
  • Phone width (390px): boot text fits, EXIT visible next to the menu button, nothing overflows.

Test harness used in this build: a Playwright script in the session scratchpad that pressed the Konami sequence or clicked the logo 5 times against a http-server dist instance, then screenshotted and logged document.documentElement.className.
